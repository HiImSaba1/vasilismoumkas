# Phase 1 — questionnaire answers, Home presentation and Pages hub

## Authorized scope

- Admin answer editing after submission without changing booking/document state or sending email.
- Home introduction readability on mobile, monochrome Meet Vasilis arrow, unbroken desktop headline words.
- Pages / Σελίδες navigation with selectable Home, About, Services and Contact cards and a return path.
- Preserve the public design, approved stored copy and animation choreography.

## Implementation

### Questionnaire

The client workspace now has an independent **Edit questionnaire answers** panel. It supports the existing native portal document and the existing legacy questionnaire source. It does not create replacement documents or reopen submitted questionnaires. The configuration editor remains separate.

Admin saves authenticate on the server, lock the existing row in a transaction, check a version fingerprint, validate permitted answer names/lengths and merge only changed fields. Unmentioned answers, custom question definitions, status, original submission date, templates and connected documents are preserved. The only writes are the answer JSON/timestamp and an activity event. No booking, payment, queue or email function is called.

Last edit time and actor type (admin/client) are recorded in reserved JSON keys. Historical records with no actor metadata display **Author not recorded**, rather than inventing an author. No database migration is needed.

Native and legacy client submissions now share row-lock ordering with admin edits and stamp client authorship. Native submission retains its existing completion/notification/automation path. Completed portal questionnaires show read-only current answers; client submission locking stays independent of admin rights.

Concurrent admin saves reject outdated versions without overwriting answers. A successful save refreshes the client workspace and invalidates portal/private questionnaire routes.

### Home

Mobile-only paragraph rules allow natural wrapping, a 200-weight rendering of the existing font, 16px size, 1.65 line height, 20px section gutters and appropriate paragraph spacing. Desktop paragraph styling remains the same. Paragraph text and paragraph boundaries come from saved Home settings and are not rewritten.

The existing RevealAnimation has an opt-in responsive line measurement path used only for the Home introduction. It retains the 1.7s duration, 0.3 stagger, easing and scroll behaviour; SplitText recalculates lines after font/width changes. Existing users of the shared component keep the original path.

The CTA preserves the saved About URL and label words, rendering a monochrome SVG arrow instead of a trailing Unicode arrow. Headline character animation now keeps characters inside unbreakable word wrappers, preserving its original timing, sizes and swap sequence.

### Pages

`/admin/pages` offers cards for Home, About, Services and Contact. Home opens its existing editor with Back to Pages. About, Services and Contact have dedicated text-input editors and Back to Pages. The existing Website settings screen remains accessible for shared footer/images and offer settings, and the SEO screen stays separate.

About fields: existing hidden H1, two biography paragraphs, public FAQ introduction and eight existing FAQs. Services fields: existing hidden H1, introduction, three service titles/descriptions and eight journey steps. Contact fields: existing hidden H1, form explanation and message placeholder; its image picker remains linked from the existing Website editor.

These are functional text editors for the hub extension requested with Phase 1. Advanced FAQ add/hide/reordering, additional imagery controls, draft publishing/revisions, expanded SEO and destination pages remain later phases. No hidden H1 is made visible and no public layout is replaced.

Each page uses a separate `site_settings` key: `public_page_about_v1`, `public_page_services_v1`, `public_page_contact_v1`. Until first save, the current approved source values remain the defaults. Saving one page does not rewrite Home, offers, SEO settings or another page. Version checks reject stale page saves.
